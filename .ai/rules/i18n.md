# Strings

Every sentence a person reads lives in `resources/i18n/en.json` under a structural key.
`StringIds.h` and `Catalogs.cpp` are **generated** from it into the build tree by
`cmake/GenStrings.cmake` — never hand-edited, never committed, regenerated by building.

The reasoning — why not `TRANS()`, why a compiled catalogue, why a hand-rolled
MessageFormat subset — is in [README.md](../../README.md#strings). This is what you have to
do.

## Writing one

```cpp
button.setTooltip (tr (StringId::transport_tempo_help));
say (tr (StringId::status_notes, Args{}.count (n)));
```

- **Never write a user-facing string in a source file.** A gate refuses a literal handed to
  `setTooltip`, `setButtonText`, `setText`, `setTitle`, `setSuffix`, `showMessage`,
  `addItem`, `addSubMenu`, `drawText` or `drawFittedText`.
- **Keys are `lowerCamel` segments joined by dots** — surface first, role last:
  `transport.tempo.help`, `param.cutoff.caption`, `dialog.removeTrack.body`. An underscore
  is banned in a segment, which is what makes `.` → `_` collision-proof, and the generator
  refuses anything else.
- **A key nobody names is an offence.** The orphan gate walks `en.json` against every
  `StringId::` the code spells. The other direction needs no test: a key the app names and
  the catalogue does not hold is a compile error, because the enum *is* the catalogue.
- **Non-ASCII goes in as `\uXXXX`**, so `en.json` stays byte-for-byte ASCII and CMake
  decodes it exactly once.
- **Arguments and plurals are ICU MessageFormat**, in the subset dew implements:
  `{name}`, `{count, plural, one {# bar} other {# bars}}`, `{sel, select, …}`. A message
  must always offer an `other` branch. Never assemble a sentence with `+`: the fragments
  are not translatable and the order is not universal.

## Things that are not translated, deliberately

- **File-format ids.** `EffectDescriptor::id`, `ParamChoice::id`, `ParamGroup::jsonKey` and
  every ValueTree identifier are what a `.dew` file spells; `effectTypeFor` matches on them.
- **`ParamSpec::suffix`.** Every one in the catalog is an SI symbol. The *word* suffixes are
  set at the call site and come from the catalogue like any other sentence.
- **Undo transaction names.** Fifty-five `beginNewTransaction` literals, read only by
  `getUndoDescription`, which nothing outside the tests calls — dew's Edit menu shows the
  command's name, not the transaction's.
- **A language's own name.** `endonymOf` holds them, because a picker shows every language
  in its own language, and because a data-driven menu can name no `StringId`.
- **The design gallery's token names** are translated only because they are cheap; they are
  developer-facing and nothing would be lost by exempting them.

## Two rules that hold the gates up

- **`tr` never returns an empty string.** A missing row returns its own dotted key, which
  is visible in a `dew_shot` render. `HoverHelpTests` and `AccessibilityTests` both read a
  tooltip and treat blank as silence, so a fallback of `""` turns two real coverage gates
  into tests that pass over nothing. Do not "fix" it.
- **The catalogue is decoded through `juce::CharPointer_UTF8`.** `juce::String`'s
  `const char*` constructor decodes ASCII; see [cpp-style.md](cpp-style.md).

## Adding a language

Drop `resources/i18n/<tag>.json` beside `en.json` and add the tag to `DEW_I18N_LOCALES` in
`src/CMakeLists.txt` — listed, never globbed, for the reason the preset sources are. Missing
keys fall back to English row by row. No C++ changes: the menu is data-driven, and the key
set comes from `en.json` alone.

The locale is chosen once, at startup, and a change takes effect next launch. `tr` returns a
reference into a table `setLocale` rebuilds, so switching under a live interface would leave
every label already built pointing into the table that was replaced.

## Known debt

The `AUTOMATION` node's stored `name` property is a **cache of an English display string**,
written by `ProjectEdits` and read only for display. `specForAutomation` is the authority,
and recomputing the name at paint time is the change that removes it. Until then a project
saved in one language carries another's labels — harmless, because nothing reads them
structurally, and `PlaylistMenus` no longer splits one apart to group its submenu.
