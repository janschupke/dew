# Strings

Every sentence a person reads lives in `resources/i18n/en.json` under a structural key.
`cmake/GenStrings.cmake` turns that one file into **two** catalogues in the build tree —
never hand-edited, never committed, regenerated by building:

| Subtree | Enum | Library | Reached as |
| --- | --- | --- | --- |
| everything but `lang.` | `StringId` | `dew_i18n`, over `juce::String` | `tr (StringId::x)` |
| `lang.` | `Msg`, with the prefix stripped | `dew_lang`, over `std::string` | `bag.text (Msg::x)` |

Two, because `dew_lang` links **nothing at all**, JUCE included, and a gate holds it to
that — so it cannot call `tr`, which returns a `juce::String`. A translator still opens one
file; which of dew's libraries holds a sentence is a fact about the link graph.

The reasoning — why not `TRANS()`, why a compiled catalogue, why a hand-rolled
MessageFormat subset — is in [Why it is this way](#why-it-is-this-way), below. This is
what you have to do.

## Writing one

```cpp
button.setTooltip (tr (StringId::transport_tempo_help));
say (tr (StringId::status_notes, Args{}.count (n)));

// and inside dew_lang, which cannot see either of those:
diagnostics.error ("E210", diagnostics.text (Msg::resolver_beatsPerBar_message), range);
```

- **Never write a user-facing string in a source file.** Three things say so, and they
  cover different ground — see [What stops the next one](#what-stops-the-next-one).
  A parameter typed `Translated` refuses a literal at compile time; one gate refuses a
  literal handed to a named sink; another refuses a literal that READS as a sentence,
  wherever it sits.
- **Keys are `lowerCamel` segments joined by dots** — surface first, role last:
  `transport.tempo.help`, `param.cutoff.caption`, `dialog.removeTrack.body`. An underscore
  is banned in a segment, which is what makes `.` → `_` collision-proof, and the generator
  refuses anything else.
- **A key nobody names is an offence.** The orphan gate walks `en.json` against every
  `StringId::` the code spells. The other direction needs no test: a key the app names and
  the catalogue does not hold is a compile error, because the enum *is* the catalogue.
- **Non-ASCII goes in as `\uXXXX`**, so `en.json` stays byte-for-byte ASCII and CMake
  decodes it exactly once.
- **A literal brace is ICU-quoted** — `try \`part lead '{'\`` — or the formatter reads it as
  an unclosed placeholder and `isWellFormedMessage` refuses the message.
- **Arguments and plurals are ICU MessageFormat**, in the subset dew implements:
  `{name}`, `{count, plural, one {# bar} other {# bars}}`, `{sel, select, …}`. A message
  must always offer an `other` branch. Never assemble a sentence with `+`: the fragments
  are not translatable and the order is not universal.

## The score language

`dew_lang` has its own catalogue, its own formatter and its own `Msg` enum, all generated
from the `lang.` subtree of the same `en.json`. `src/lang/MessageCatalog.h` argues why it
is a second one rather than a call into the first.

- **`Msg` is named per CALL SITE, never per diagnostic code.** Codes are many-to-many with
  wording: `E103` is one error two parsers report, and *"no channel called `x`"* is
  reported under three codes. `Diagnostic::code` is untouched by any of this.
- **The locale is a parameter, and nothing global holds one.** `DiagnosticBag` takes one
  and `bag.text (Msg::x)` resolves it; `lang::compile`, `lang::completionsAt`,
  `resolveChord` and `docs::schemaJson` all take one defaulting to the reference.
  `dew_lang` has no mutable global state at all, and the library whose whole claim is
  determinism should not gain its first: two compiles of one score in one process must not
  be able to differ by something that changed between them.
- **`src/ui/ScoreLocale.h` is where the two locale types meet.** `dew_i18n` holds a BCP-47
  tag because that is what a person chose and what `Settings` stores; `dew_lang` holds an
  enum because it has neither a `juce::String` to keep a tag in nor a global to keep one
  in. `dew_ui` is the lowest layer that can see both.
- **The formatter is written twice, deliberately.** The alternative is a layering edge from
  `dew_lang` to `dew_i18n`, which puts `juce_core` on the link line of `dew_docs` — the
  tool whose whole job is to demonstrate that the score language needs nothing. The plural
  RULES are not duplicated: `resources/i18n/plurals.txt` declares the CLDR families once
  and the generator emits `PluralTable.h` into both build trees byte for byte, with a test
  comparing the copies. The two parsing loops are held to one table of cases,
  `tests/MessageFormatCases.h`, run by both suites.
- **`nameOf (ValueKind)` returns a `Msg`; `nameOf (BlockKind)` returns a `const char*`.**
  The first is prose — *"a tempo, like `96 bpm`"* — and the second is the keyword `song`,
  which is syntax. The pair reading differently is the point.
- **`E207` is the one sanctioned interpolation of prose.** It splices `nameOf (ValueKind)`
  into *"`{key}` takes {kind}"*: thirty-one kinds against one frame is thirty-one sentences
  to avoid one substitution, and the argument is a noun phrase rather than a bare noun. A
  locale that has to restructure has `select` available. Every other frame that spliced a
  noun became whole messages.

## Content a file holds

A name written into a `.dew` or a `.dewpreset` is **the author's data from the moment it
is written**, not a label the program keeps re-deciding. So:

- **A new project's names are translated at creation.** `ProjectFactory::createDefault`
  takes a locale; File > New passes `activeLocale()`. Reopening never re-translates, and a
  shared project reads the same for both people.
- **The DEFAULT is the reference locale, and that is load-bearing.** Six committed demos,
  three byte-pinned bakes and fifty test fixtures build from the same factory and are
  compared against committed files. They get the safe answer by not thinking about it; the
  risky value is the one you have to spell. It used to be an accident — the names were
  literals, and nothing in a console tool happens to call `setLocale`.
- **A preset is named by its FILE.** `PresetFactory::Entry::fileName` is the stable id;
  `PresetLibrary::displayName` looks the entry up by it and resolves in the active locale.
  The `.dewpreset` keeps a real English name so the format stays openable and diffable, and
  `PresetFactory::buildFor` writes it in the reference locale. The `ParamChoice` precedent,
  exactly: the id is what the file stores, the `StringId` is what a person reads.
- **A preset's CATEGORY is stored as its id, and only its id.** `PresetCategory` is an
  enum with a `const char*` id and a `StringId` label, and a `.dewpreset` holds the id
  (`"pads"`). A category is not the author's data the way a name is - it is a fact about
  where the preset belongs - so nothing writes the label to a file, and "what a preset
  FILE holds does not depend on a locale" stays true without the writer having to think
  about it. An id this build does not know reads back as no category rather than as a
  refusal: a preset from a later dew is still a sound you can load.
- **`ProjectFactory::Demo::menuName` is a `StringId` outright**, because a demo's menu name
  is never written into a file — the demo's own project name is — so there is no stored
  copy to keep in step.
- **A demo's CONTENT names are never translated.** `channelNamed` matches a score's
  declared channel against a project channel **by name**, so `pad`, `swell`, `sub`, `bell`
  and `answer` are join keys, not labels. Its SCAFFOLD is translated, in the reference
  locale: "Channel 3" comes from `project.channelN` through `trIn`, so it reads the same
  bytes on every machine whatever language dew is running in.
- **An automation's name is NOT written into a file**, and that is the one place this rule
  is inverted. It is a display string — "Kick > Filter > Cutoff" — rather than anything an
  author typed, so a stored copy was a cache of ENGLISH in a file that outlives the
  language it was saved in. `automationDisplayName` recomputes it from the four properties
  that say what the clip drives, and the property is retired: a project already saved
  loads without a warning about it.

Two consequences are written down rather than fixed, because both are the format telling
the truth about itself:

- A score that says `channel kick` binds to the default project's "Kick". In another
  language it creates a channel instead of adopting one — the same behaviour as any other
  name mismatch, now differing by locale.
- Duplicating a pattern asks whether its name is still the auto-generated one, to choose
  between "Pattern 3" and "Pattern 2 copy". Across languages that reads as renamed.
  Answering it properly means storing a flag, which is a file-format change to improve a
  name.

## Things that are not translated, deliberately

- **File-format ids.** `EffectDescriptor::id`, `ParamChoice::id`, `ParamGroup::jsonKey` and
  every ValueTree identifier are what a `.dew` file spells; `effectTypeFor` matches on them.
- **`ParamSpec::suffix`.** Every one in the catalog is an SI symbol. The *word* suffixes are
  set at the call site and come from the catalogue like any other sentence.
- **Undo transaction names.** Read only by `getUndoDescription`, which nothing outside the
  tests calls — dew's Edit menu shows the command's name, not the transaction's. They are
  spelled `TransactionName { "Rename channel" }`, which is what makes that a shape a gate
  can strip rather than a licence `setProperty` and every `attach` helper would need.
- **A language's own name.** `endonymOf` holds them, because a picker shows every language
  in its own language, and because a data-driven menu can name no `StringId`.
- **Language syntax.** A block keyword, a mode name, a duration literal, a chord symbol, a
  counterpoint rule's name, `Completion::text` — every one is a token the compiler reads
  back, and `nameOf (BlockKind)` answers with it.
- **The diagnostic renderer's own furniture.** `severityName`, the `" = note: "` /
  `" = help: "` markers and the `" here:"` that follows a related label in
  `Diagnostics.cpp` are a compiler-output format in the clang/rustc idiom, consumed by
  `dew_score` and by tests. Nothing in the application renders it — `render` takes no
  locale, and the score editor reads a diagnostic's own fields instead. `dew_score` and the MCP endpoint
  compile in the reference locale for the same reason; the score editor passes the reader's.
- **`ProjectSchema.cpp`'s defaults.** The `{ ids::name, "Channel" }` rows are the file
  format's default VALUES, and every creation path overwrites them immediately.
- **Everything an agent reads over MCP.** Tool names, summaries, argument documentation and
  the guide resources are English and live in `src/control/`. They are read by a model
  rather than by a person, and a tool's NAME is a wire contract in the way an effect's id
  is. The consent and connections panels are ordinary interface and take keys like
  anything else — see [mcp.md](mcp.md).
- **The design gallery's token names** are translated only because they are cheap; they are
  developer-facing and nothing would be lost by exempting them.
- **The starter score's body.** `src/ui/ScoreEditorLayout.h` holds a score, and `channel`,
  `rhythm` and `voicing` are keywords the compiler reads back — a translated one would not
  compile. The four lines of English above it are prose that happens to be shipped as a
  comment, and they are `score.starter.intro`.
- **A shell command.** `claude mcp add …` is typed into a terminal and is the same
  characters everywhere. It is held as a `shellCommand` constant, so what protects it is a
  shape rather than a file name in an exemption list.
- **A demo's content, and the OS's own vocabulary.** `src/model/demos/` holds names a score
  binds to; a path component, a thread name and a log line are read by a filesystem, a
  debugger and whoever is working on dew.

## Two rules that hold the gates up

- **`tr` never returns an empty string.** A missing row returns its own dotted key, which
  is visible in a `dew_shot` render. `HoverHelpTests` and `AccessibilityTests` both read a
  tooltip and treat blank as silence, so a fallback of `""` turns two real coverage gates
  into tests that pass over nothing. Do not "fix" it.
- **The catalogue is decoded through `juce::CharPointer_UTF8`.** `juce::String`'s
  `const char*` constructor decodes ASCII; see [cpp-style.md](cpp-style.md).

## Adding a language

Drop `resources/i18n/<tag>.json` beside `en.json` and add the tag to `DEW_I18N_LOCALES` in
`src/CMakeLists.txt` — listed, never globbed, for the reason the preset sources are. Missing
keys fall back to English row by row. No C++ changes: the menu is data-driven, the key set
comes from `en.json` alone, and both catalogues and both `Locale` enums are generated from
it.

Add the language's plural family to `resources/i18n/plurals.txt` if it is not already
there. Exactly one family says `languages *` and is the two-form default; a language named
nowhere gets it, which is the safest wrong answer because every message declares `other`.

The locale is chosen once, at startup, and a change takes effect next launch. `tr` returns a
reference into a table `setLocale` rebuilds, so switching under a live interface would leave
every label already built pointing into the table that was replaced.

## What stops the next one

Three mechanisms, and they are not alternatives: each sees what the others cannot.

**A type, where a helper would launder the literal.** `paint::emptyState`,
`paint::sectionHeading`, `paint::styleCaption` and `RandomizePanel::show` take a
`Translated` — `src/i18n/Translated.h` — which converts from a `StringId` or an
already-resolved `juce::String` and **deletes** the `const char*` constructor. A literal
cannot reach the `juce::String` one either, because that would be two user-defined
conversions in one implicit sequence. This is the strongest of the three and the only one
with no exemption list: `paint::emptyState` drew ten sentences of raw English for a year,
because the `drawText` a gate can see was inside the helper and its argument was a
variable by the time it got there.

**The sink gate**, `tests/SourceGateStringsTests.cpp`, refuses a literal handed to
`setTooltip`, `setText`, `setTitle`, `setDescription`, `postAnnouncement`, `addItem`,
`addTab`, `drawText`, a diagnostic's message and label, and a dozen more. It looks through
a `juce::String (…)` or `CharPointer_UTF8 (…)` wrapper, because that is how the score
editor's own heading survived the whole first extraction pass. It is the one that catches a
one- or two-word LABEL — "Rename", "Mixer" — which no shape test can tell from an id.

**The prose gate**, `tests/SourceGateProseTests.cpp`, asks the literal rather than the call:
a space and two runs of lower-case letters is a sentence, and a literal that begins or ends
mid-phrase is a sentence being ASSEMBLED. That third clause is what enforces *never
assemble a sentence with `+`* — `+` launders every fragment away from whatever sink it
reaches, which is how `warnings.add` reported nothing at all while being on the sink list.
Its exemptions are classes rather than conveniences (`src/control`, the diagnostic
renderer, the crash handler, the demos' content, the starter score's body), and its
stripped call shapes each say what their literal IS: a `static_assert`, a
`TransactionName`, a switch arm returning a name, a `ParamSpec` row's SI suffix.

`TransactionName` is the same idea as `Translated`, pointed the other way: an undo step's
name is one of the few English literals that is NOT read by anyone, and naming the type is
what lets a gate strip it by shape instead of excusing `setProperty` outright.

## Why it is this way

Every sentence a person reads is a key in `resources/i18n/en.json` —
`transport.tempo.help`, `param.cutoff.caption` — and the code names the key, never the
sentence. `StringIds.h` and the catalogue tables are generated from that file into the
build tree by a CMake script, so a key the app names and the catalogue does not hold is a
compile error rather than a blank label.

**JUCE's own mechanism was rejected rather than overlooked.** `TRANS("Save As...")` keys
the translation on the English sentence, so correcting a typo orphans every translation of
it, two identical English strings with different meanings collapse into one entry, and
nothing can enumerate the keys that exist. Keys are structural here; the English text is
just the first translation.

**The message syntax is ICU MessageFormat, and the implementation is not ICU.** Plurals
and substitutions use the syntax i18next, Fluent, Android and iOS have all converged on, so
the catalogue is a shape a translator's tooling already reads — but ICU itself is a pinned
dependency, a `THIRD_PARTY.md` row and tens of megabytes of CLDR data for the three
constructs dew uses. The subset is a few hundred lines and the plural table is written out
per language, because `cs` and `pl` agree on small numbers and diverge above them and
folding them together is how a locale silently inherits another's rule.

**It is implemented twice, and the duplication is proved rather than trusted.** The score
language cannot reach `juce::String`, so it has its own loop over `std::string`. What makes
that survivable is that neither half is checked against its own idea of correct: the plural
rules are generated into both from one authored file and a test compares the two emitted
copies byte for byte, and the two parsing loops run the same table of cases in two suites,
so a fix applied to one and not the other fails in the suite that did not get it. The
alternative — a layering edge from `dew_lang` to `dew_i18n` — would put `juce_core` on the
link line of `dew_docs`, and that tool exists to prove there is nothing on it.

**The catalogue is compiled in, not loaded.** `dew_i18n` links `juce_core` and nothing
else, so it cannot read itself off disk — which would also be file I/O two layers below
`dew_io`, the only layer allowed to touch a file. A catalogue that has to be compiled in
cannot drift from the build that ships it.

**The locale is fixed at launch.** `tr` returns a *reference* into a table built once when
the locale is chosen, so drawing a label costs no allocation — cheaper than the literal it
replaced, since `juce::String` has no small-string optimisation. The price is that changing
language needs a relaunch, and the menu says so; the alternative was handing every caller a
copy, forever.

A missing row returns its own dotted key rather than an empty string, which is visible in a
`dew_shot` render. That is not politeness: two coverage gates read a control's tooltip and
treat blank as silence, so a fallback of `""` would turn both into tests that pass over
nothing.

Several tests enforce a convention by scanning the sources, and each passes silently when
it finds nothing; `SourceGateTests` checks that walk against the libraries' own source
lists in both directions, so code that moves out of `src/` cannot quietly disarm them and
a file that never joins a library cannot sit there uncompiled while appearing to be built.

Each of those gates lets one or two places break its rule, because a rule has to be
declared somewhere. **An exemption names a path and has to earn its place**: an entry that
suppresses nothing is reported as an offence of its own, so a definition site that moves
is named rather than silently escaping. It used to be a bare file name — and a name is not
a property a file keeps, which is how five gates went red during the split above, each for
a file that had done nothing wrong. Ten of the twenty-one entries turned out to suppress
nothing at all: `Tokens.h` was exempt from the gate on drawn radii while drawing nothing,
`Ids.h` from a gate on names it spells with the preprocessor, and two files that build the
document held a standing licence to write an undoable property by hand.

Those gates read stripped code, not the file as written. Every one of them used to ask
whether a line began with a comment marker, which dew's doc comments — continuing without
a leading asterisk — defeat, so three gates were held green by a wrapped sentence. The
reader tracks strings as well, and that mattered most: a gate quoting a comment marker in
its own predicate opened a comment that swallowed the rest of the file, which is why
`SourceGateTests.cpp` measured 301 code lines while holding 667.

It tracks RAW strings too, and that hole was the same shape one level down. A string was
tracked within a line only, so `R"SCORE(` read as one that never closed and every line
after it was read as ordinary code — which deleted the starter score's own `//` lines as
if they were C++ comments. The four sentences a person reads on opening the Score tab were
invisible to every gate in the suite. Each physical line of a raw string is requoted now,
so a line number still points at the sentence that offends and the delimiters cannot
unbalance the statement joiner.

**A sink list could not have finished this.** The gate that refuses English at a named call
was extended eleven times and still could not see sixty per cent of what was left, because
the failures were not missing names: a helper turned the literal into a variable before it
reached a listed sink, a summary was assigned to a member and drawn three hundred lines
later, and a concatenation moved the fragments away from the call entirely — which is how
`warnings.add`, a listed sink, reported nothing at all. What closed those was asking the
LITERAL whether it reads as a sentence, and giving the helpers a parameter type a literal
cannot convert to. The three mechanisms are described under [What stops the next
one](#what-stops-the-next-one); the point of having three is that each sees what the
others cannot.

**No file is over 400 lines of code**, and a gate says so. The number is the tree's own
p90 rather than a preference — the same way `ColumnLimit` is 100 because the p99 line is
96 characters — and it counts CODE, comments and blanks removed, because these headers
carry long doc comments on purpose and a raw count would punish them. There is no
exemption list: a gate with one is a ratchet, and this is meant to be a rule. Tests and
tools are held to it too.

Getting there took thirty commits. The largest file was `lang/Resolver.cpp` at 1,740
lines and is now 441; `PlaylistComponent.cpp` was 1,894 and the class is now five files —
component, view, paint, gestures and menus — with its track header a class of its own.
Three shapes did the work — the same class in a second translation unit, a nested class
promoted to its own, and a file-local state machine given a name so it can be defined in
more than one place — and which one applies is a judgement about how much of its host a
piece of code actually reads.
